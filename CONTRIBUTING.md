# Contributing to TheLook

We work **branch → pull request → review → merge**. Nobody pushes to `main` directly.

## One-time setup
```bash
git clone https://github.com/aposalik/TheLook.git
cd TheLook/web
npm install
cp .env.local.example .env.local   # then paste YOUR OWN YouCam API key + secret
npm run dev                          # http://localhost:3000
```
> Each developer uses their **own** YouCam API key in their **own** `.env.local`.
> `.env.local` is git-ignored and must **never** be committed.

## Working on a task
1. Pick the Issue assigned to you.
2. Branch off the latest `main`:
   ```bash
   git checkout main && git pull
   git checkout -b feature/<short-name>    # e.g. feature/cart
   ```
3. Do the work, committing in small steps:
   ```bash
   git add -A && git commit -m "Add cart summary + mock checkout"
   ```
4. Push and open a PR (link the Issue it closes):
   ```bash
   git push -u origin feature/<short-name>
   gh pr create --fill          # add "Closes #<issue-number>" in the body
   ```
5. A reviewer reads the diff, requests changes or approves, then **squash-merges**. Delete the branch.

## Rules
- `main` always runs. Don't merge anything that breaks `npm run build`.
- Keep PRs small and focused on one task.
- Never commit secrets, `node_modules`, the Python `.venv`, or render outputs (all git-ignored).
- Dev against `MOCK=1` (in `.env.local`) to avoid spending YouCam credits while building UI.

## Project map
- `web/` — the Next.js app (UI + `/api` proxy).
- `web/lib/` — `youcam.ts` (render API client), `recommend.ts` (outfit brain).
- `data/` — `catalog.json`, `compat_matrix.json` (generated by the pipeline).
- `_experiments/` — the offline catalog pipeline + research scripts (Python).
- `REQUIREMENTS.md` · `DESIGN.md` · `PHASES.md` — what/how/plan.
